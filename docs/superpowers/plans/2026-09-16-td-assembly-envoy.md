# The Woods — TD Assembly Implementation Plan (Embody/Envoy)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the live TouchDesigner project (`td/theWoods.toe`) — create the five COMP networks whose Python logic and build instructions already exist on the `td-port` branch — using Envoy MCP tools, with Embody externalization keeping everything git-diffable.

**Architecture:** The `td-port` branch already contains all Python logic modules (TD-free, 72 pytest tests) and glue scripts (`*_exec.py`) plus per-COMP build instructions in `td/README.md`. This plan executes those instructions inside TouchDesigner via Envoy: create `.toe`, install Embody, then build/param/wire each COMP network, externalize each op, and verify end-to-end with stub inputs.

**Tech Stack:** TouchDesigner 2023.10k+ / 2025 (POPs required), Embody `.tox` (~/Developer/repos/Embody), Envoy MCP server (localhost:9870, bridge in `.mcp.json`), existing branch Python.

**Spec:** `docs/superpowers/specs/2026-09-15-td-port-design.md` (OSC contract) + `td/README.md` (build instructions — the authoritative per-COMP steps this plan operationalizes).

## Global Constraints

- Every Envoy session: call `get_td_status` first; after any create/connect, run `get_op_errors` with `recurse=true`.
- Never hand-edit `externalizations.tsv` — Embody owns it (`externalize_op` / `save_externalization` only).
- Never set `file`/`syncfile` params manually — create DATs via `create_op` → `set_dat_content` → `externalize_op`; DAT content is synced from the branch files, not retyped.
- Never guess network paths: `query_network` on `/` first; current pane owner via `execute_python` (`result = ui.panes.current.owner.path`).
- Load project-local skills before first MCP call (`mcp-tools-reference`), before writing TD Python (`td-api-reference`), before `create_op` (`create-operator`), before `externalize_op` (`externalize-operator`).
- All DAT file paths relative to the `.toe` at `td/` (e.g. `data/tracks.tsv`).
- op() paths in the existing glue assume: scripts live inside their COMP (`../X` sibling, `../../comp/X` cross-COMP). Node names must match exactly: `depthIn`, `tracking`, `trackUI`, `control`, `network` at root; inside `tracking`: `inOverhead`, `targets`, `targetscook`; inside `control`: `controlcook`, `lights`; inside `trackUI`: `background`, `tracks`, `panelcook`; inside `network`: `netcook`, `oscOut`, `oscOutBcast`, `oscIn`, `nodeStatus`.
- One commit per task (or per logical batch within a task), signed Jesse Garrison <jesse@nightlight.io>.
- Work happens on the `td-port` branch in the main checkout after merge (or in `.worktrees/td-port` if not yet merged).

- [ ] **Step 2: Build the chain (per td/README.md "## tracking COMP")**

```
create_op  family="TOP" opType="in"      name="inOverhead"  path="/project1/tracking"
create_op  family="TOP" opType="threshold" name="thresh1"   path="/project1/tracking"
create_op  family="TOP" opType="dilate"   name="dilate1"   path="/project1/tracking"   # then blur — or single pipeline per README
create_op  family="CHOP" opType="blobtrack" name="blob1"   path="/project1/tracking"
```
